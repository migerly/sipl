# SIPL Toolkit — індивідуальний навчальний проєкт

Обрані завдання: CORE-01 (0,5), CORE-02 (1,5), CORE-03 (2), CORE-04 (1),
CORE-05 (1), CORE-06 (1), VIS-01 (1,5), FORM-04 (1,5). Разом — 10 балів;
оцінювання визначає викладач.

Третій приклад: `py sipl.py run gcd.sipl --var M=12 --var N=8`
виконує алгоритм Евкліда, результат M = N = 4.

Потрібен Python 3.9 або новіший. У чистому середовищі можна створити
середовище `py -m venv .venv`, встановити залежності командою
`.\.venv\Scripts\python -m pip install -r requirements.txt` і використовувати
`.\.venv\Scripts\python` замість `py` у командах нижче.

Покриття саме interpreter.py тестами test_interpreter і test_trace виміряно
coverage.py: 97% рядків. Команди: `py -m coverage run --source=interpreter -m unittest test_interpreter test_trace`
та `py -m coverage report -m` після окремого встановлення coverage.

## Виведення для контекстно-вільних граматик (FORM-04)

`py cfg_explorer.py grammar_example.json aabb --max-steps 6 --output derivation.json`
шукає лівосторонні виведення слова aabb для S → aSb | ε. Для правосторонніх
додайте `--direction right`. Порожній список у rules означає ε-правило;
кожна права частина — список символів, ліві частини — імена нетерміналів,
усі інші символи — термінали. Для багатосимвольних терміналів другий аргумент —
JSON-масив. Експорт містить усі знайдені в межах пошуку дерева й кроки.
max_steps — межа числа застосованих правил, max_states і max_trees також
обмежують пошук. Якщо за цих меж слово не знайдено, це не доводить, що
воно не належить мові. truncated позначає досягнення хоча б однієї межі.

## Git

Викласти треба одну папку проєкту з кодом, граматикою, тестами, прикладами,
requirements.txt, README.md та .gitignore. Віртуальне середовище і __pycache__
до Git не додаються. Історію комітів студент формує під час роботи.

Єдиний інтерфейс (етап 5): `py sipl.py check example.sipl`,
`py sipl.py parse example.sipl`, `py sipl.py run example.sipl`,
`py sipl.py trace loop.sipl --var x=2 --var y=3`. Додайте `--json`
після назви файлу для структурованого результату. Результат має поля
`schema_version` (1), `status`, `command`, а також `ast`, `state`,
`events` або `error` залежно від команди й результату. Коди: 0 — успіх,
1 — помилка синтаксису або виконання, 2 — помилка читання чи аргументів.
Помилки обробки самих аргументів створює argparse, вони можуть бути текстовими.

Набір перевірки відповідності (етап 6): `py conformance_runner.py`.
Файл conformance.json не містить коду конкретного інтерпретатора: format_version —
версія формату, cases — приклади, id — назва, source — програма,
initial — вхідний стан, max_steps — необов'язковий ліміт, expect — очікуваний
статус та повний стан або вид помилки. За потреби іншу реалізацію можна перевіряти
на тих самих даних через адаптер до її інтерфейсу. Для прикладу precedence також
задано очікуване AST без позицій, яке runner порівнює зі структурою parse.

Дерево синтаксичного розбору: `py visualize.py example.sipl`. Формати:
`--format json --output tree.json` та `--format dot --output tree.dot`.
DOT можна перетворити на SVG окремо встановленою програмою Graphviz:
`dot -Tsvg tree.dot -o tree.svg`. Кожен вузол містить фрагмент тексту і позиції.
Дерево розбору зберігає токени begin/end та інші деталі, на відміну від AST.

Індивідуальний проєкт; заплановані CORE-01–CORE-06, VIS-01, FORM-04 (10 балів). Цей архів містить граматику, AST та початковий інтерпретатор; решта модулів і повна перевірка вимог ще попереду.

Потрібні Python 3 та пакет Lark. У Windows у папці проєкту:

```
py -m pip install -r requirements.txt
py check.py example.sipl
py check.py --ast example.sipl
py run.py example.sipl
py run.py loop.sipl --var x=2 --var y=3
py run.py example.sipl --trace
py run.py loop.sipl --var x=2 --var y=3 --json
py -m unittest -v
```

check.py перевіряє синтаксис і не виконує програму. run.py виконує програму й виводить кінцевий стан. --var задає вхідні значення; звернення до відсутньої змінної повідомляє про помилку. --max-steps обмежує кількість присвоювань, skip і перевірок умов. При перевищенні ліміту виконання переривається; це не доводить нескінченність циклу. Обидва операнди логічного або обчислюються. Тести граматики містять 11 правильних і 12 неправильних програм.

Трасування: --trace виводить події по рядку, --json повертає один JSON-об'єкт зі статусом, кінцевим станом і подіями. Програмний доступ: після machine = Interpreter() і machine.run(program) події знаходяться у machine.events. Події before_statement та after_statement позначають початок і завершення оператора, variable_changed — зміну змінної, condition_checked — перевірку умови, completed — завершення програми, error — помилку виконання. Кожна подія містить копію стану; події для вузлів містять позиції у файлі. На помилці after_statement для незавершеного оператора відсутня.

Прапорець --ast виводить абстрактне синтаксичне дерево у форматі JSON. Опис типів вузлів міститься у sipl_ast.py. SourceSpan зберігає рядок, стовпець та позиції початку й кінця; кінець не включається. Нумерація рядків і стовпців починається з 1, позицій у рядку тексту — з 0.

Граматика спирається на «Лекція 1–2. Мова SIPL», слайди 4, 8, 10. Числа — цілі. Імена змінних — латинські літери, цифри та підкреслення, починаються з літери або підкреслення; службові слова зарезервовані. Пробіли та переноси рядків ігноруються. Для зручності введення поряд із лекційними ¬ та ∨ підтримуються not та or; це зафіксований варіант запису. `*` має вищий пріоритет за `+` та `-`, оператори однакового пріоритету асоціюються зліва. Тіло if та while — один оператор; для послідовності використовується begin/end. Для неоднозначних конструкцій вибір дерева поки потребує додаткової перевірки перед використанням інтерпретатором.
