# SIPL Toolkit

Навчальний інструмент для роботи з мовою SIPL та контекстно-вільними граматиками. Проєкт перевіряє синтаксис SIPL-програми, будує абстрактне синтаксичне дерево (AST), виконує програму і відображає події її виконання.

## Встановлення на Windows

Потрібен Python 3.9 або новіший. Відкрийте PowerShell у папці проєкту і встановіть залежність із файлу requirements.txt:

~~~powershell
py -m pip install -r requirements.txt
~~~

Перевірити встановлення й запустити автоматичні тести:

~~~powershell
py -m unittest -v
py conformance_runner.py
~~~

Для ізольованого встановлення можна створити віртуальне середовище: `py -m venv .venv`, далі `.\.venv\Scripts\python -m pip install -r requirements.txt`. У наступних командах замість `py` використовуйте `.\.venv\Scripts\python`.

## Команди SIPL

~~~powershell
py sipl.py check example.sipl
py sipl.py parse example.sipl
py sipl.py run example.sipl
py sipl.py run loop.sipl --var x=2 --var y=3
py sipl.py trace loop.sipl --var x=2 --var y=3
~~~

- **check** перевіряє синтаксис;
- **parse** будує AST та виводить його у JSON;
- **run** виконує програму і показує кінцевий стан змінних;
- **trace** додатково показує події під час виконання.

Параметр `--var x=2` задає початкове значення; його можна повторювати. Додайте `--json` для структурованого результату. Ліміт `--max-steps` обмежує кількість кроків; його досягнення саме по собі не доводить нескінченності циклу.

### Приклади

- `example.sipl`: присвоювання; кінцевий стан — x = 2, y = 5.
- `loop.sipl`: множення повторним додаванням; для x = 2, y = 3 отримаємо z = 6, k = 0.
- `gcd.sipl`: алгоритм Евкліда відніманням для додатних чисел. Команда `py sipl.py run gcd.sipl --var M=12 --var N=8` дає M = 4, N = 4.

## Граматика та структура

Файл `sipl.lark` спирається на БНФ і пріоритети з лекції «Мова SIPL», слайди 4, 8 та 10. Підтримано присвоювання, послідовність, блоки begin/end, if/then/else, while/do і skip, цілі числа, арифметику, порівняння та логічні операції. Крім символів ¬ і ∨, передбачено текстові записи not та or.

Імена змінних складаються з латинських літер, цифр і підкреслення та починаються з літери або підкреслення. Множення має вищий пріоритет за додавання й віднімання. Для послідовності всередині гілки або циклу використовується блок begin/end.

`check.py` розбирає текст за граматикою; `sipl_ast.py` створює власні вузли AST; `interpreter.py` виконує їх; `sipl.py` надає консольні команди. SourceSpan зберігає позиції вузла у вихідному тексті: номери рядка і стовпця починаються з 1, індекси символів — з 0; кінцева позиція виключна.

Стан програми — значення її змінних. Звернення до змінної, якої немає у стані, спричиняє помилку. Для логічного «або» обчислюються обидва операнди.

## Трасування

Доступні події before_statement, after_statement, variable_changed, condition_checked, completed та error. Кожна подія містить копію стану; події вузлів також містять позицію в тексті. Програмний доступ: після запуску через Interpreter події доступні в `machine.events`.

JSON-результат CLI містить schema_version, status і command, а залежно від команди — ast, state, events або error. Код виходу 0 означає успіх, 1 — помилку синтаксису чи виконання, 2 — помилку читання або аргументів. Повідомлення argparse про неправильні аргументи можуть бути текстовими навіть із `--json`.

## Дерево синтаксичного розбору

~~~powershell
py visualize.py example.sipl
py visualize.py example.sipl --format json --output tree.json
py visualize.py example.sipl --format dot --output tree.dot
~~~

Кожен вузол пов'язаний із фрагментом вихідного тексту та його позицією. Для перетворення DOT на SVG необхідна окремо встановлена програма Graphviz:

~~~powershell
dot -Tsvg tree.dot -o tree.svg
~~~

## Виведення для КВ-граматик

Файл grammar_example.json задає граматику S → aSb | ε. Приклад пошуку:

~~~powershell
py cfg_explorer.py grammar_example.json aabb --max-steps 6 --output derivation.json
~~~

Для правостороннього виведення додайте `--direction right`. У файлі граматики rules містить альтернативи для кожного нетермінала; права частина — список символів, порожній список позначає ε. Інші символи вважаються терміналами. Другий аргумент задає слово із символів; для багатосимвольних терміналів передбачено JSON-масив.

Результат містить знайдені послідовності й дерева виводу. Пошук обмежений параметрами max_steps, max_states і max_trees. Якщо в заданих межах виведення не знайдено, це не доводить, що слово не належить мові. Поле truncated показує, що пошук був обмежений.

## Тестування

Файли test_*.py містять автоматичні тести. Незалежні від коду приклади містяться у conformance.json: source — програма, initial — початковий стан, expect — очікуваний стан або тип помилки; для одного прикладу задано очікувану структуру AST. conformance_runner.py перевіряє ці дані через CLI проєкту; для іншої реалізації потрібен відповідний адаптер.

Раніше перевірено 24 тестові методи та 10 прикладів відповідності. Покриття саме файлу interpreter.py тестами test_interpreter і test_trace становило 97% рядків; це не показник покриття всього проєкту. Для повторення після окремого встановлення coverage:

~~~powershell
py -m coverage run --source=interpreter -m unittest test_interpreter test_trace
py -m coverage report -m
~~~

## Відомі обмеження

- Для неоднозначних вкладених конструкцій потрібна додаткова перевірка вибору дерева відповідно до матеріалів курсу.
- Очікувану структуру AST у наборі відповідності варто розширити додатковими прикладами.
- На Windows файли SIPL, збережені як UTF-8 з BOM, можуть викликати помилку синтаксису; використовуйте UTF-8 без BOM. Для прикладів, що містять лише ASCII-символи, можна використовувати ASCII.
- Набір модулів заявлено на 10 балів; повноту відповідності критеріям оцінює викладач.
